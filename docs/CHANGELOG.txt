## 2026-11-16 — Phase 3a review fixes: terminal sanitizing, jq strings, body flags
Phase: Phase 3 / v0.1.0
Spec:  §10.1, §10.2, §11.1

Security:
- Server-provided text was written to the terminal unchanged, so a
  repository description (and in 3b an issue title) could inject escape
  sequences such as OSC 52 (clipboard write), OSC 8 links or screen clearing.
  New output.Sanitize replaces C0 controls (except tab/newline) and DEL with
  caret notation and C1 controls with U+FFFD. Applied to every table cell and
  header (TTY and TSV), to `repo view` (TTY and raw) and to `--jq` string
  results on a terminal.
Fixed:
- `--jq` printed string results JSON-quoted; like gh they are now raw lines.
- `--body ""` was treated as "no body": it now counts as given
  (BodyOptions.Provided, needed by `issue edit` to clear a body) and
  conflicts with `--body-file`. `--body-file ""` is a usage error.
- `--editor` without a terminal started the editor and could hang (§11.1);
  it is now a usage error (BodyContext.CanPrompt).
Tests:
- go test ./..., go vet, staticcheck; GOOS=windows/darwin builds. Race tests
  not run locally (no gcc, B-35).
Notes / next steps:
- Not fixed (minor): TimeAgo uses time.Since (no injected clock), pager/editor
  command lines split on spaces (Windows paths, B-28), tablerender twice
  repeats rows, isBrokenPipe matches error text, truncation after a ZWJ (B-41).
- --template output is not sanitized yet (template text may legitimately
  contain colors); decide before issue/PR templates matter.

## 2026-11-13 — Phase 2b review fixes: clone hardening, delete confirmation
Phase: Phase 2 / v0.0.3
Spec:  §5.3, §7.4, §8.3

Security:
- `repo clone`, `repo create --clone` and `repo fork --clone` passed the
  server's clone_url and repository name to `git clone` without "--". A
  malicious or compromised server could return clone_url
  "--config=core.sshCommand=<cmd>" (or "--upload-pack=<cmd>") and run a local
  command (reproduced with git 2.56). Fixed:
  - `git clone [<gitflags>] -- <url> <dir>` and `git remote add -- upstream
    <url>`;
  - clone URLs must parse as https/http/ssh (internal/git.ParseURL); options,
    whitespace/control characters, file://, local paths and `<helper>::`
    transports are refused;
  - a server-provided name is used as the directory only if it is one safe
    path element (no '/', '\', ':', leading '-', '.', '..').
  - Regression test TestCloneRejectsMaliciousServer; verified that it fails
    with the old code ("a command from the server response was executed").

Changed:
- `repo delete` on a terminal requires typing OWNER/REPO (or HOST/OWNER/REPO,
  case-insensitive) like gh; "y" is no longer enough. Non-TTY still needs
  --yes.
- `repo create` conflict message: "repository NAME already exists" instead of
  "/NAME" for user repositories.
- scripts/test-forgejo.sh: picks the host port before starting the container
  and sets ROOT_URL to it, so API clone URLs work from the host.

Added:
- Tests: delete confirmation (wrong answers send no request), malicious
  clone URL/name cases, explicit destination with an odd server name,
  git.RunWithIO; integration: `repo clone` of an organization repository
  against Forgejo 15/17. Clone unit tests now use https URLs rewritten with
  url.<path>.insteadOf.
- BACKLOG B-39: `repo rename` should update the local remote (gh does).

Tests:
- go test ./... pass; gofmt, go vet (linux/windows/darwin, -tags integration),
  staticcheck clean; govulncheck: none.
- scripts/test-forgejo.sh: pass against Forgejo 15.0.11 and 17.0.1.
- Coverage: git 91.1 %, cli/repo 81.7 %.

## 2026-11-13 — Phase 1 (part 2): `fjo api`
Phase: Phase 1 / v0.0.2a
Spec:  §5.9, §7.4, §9.4, §16 Phase 1

Added:
- internal/cli/api (package apicmd), registered in internal/cli/root.go:
  `fjo api <endpoint>` with --hostname (no -h, as gh), -X/--method,
  -F/--field (true/false/null/int64, @file, @-), -f/--raw-field,
  -H/--header, --input FILE|-, --paginate, -i/--include, --silent.
  - Method defaults to GET, POST when fields or --input are given and -X
    is not set (gh).
  - GET/HEAD fields -> query string; with --input the fields also go to the
    query; otherwise a JSON object. Nested keys `a[]=` and `a[b]=`;
    duplicate / conflicting keys are usage errors.
  - --input sets Content-Type: application/json unless -H overrides it.
  - --paginate: GET only, uses Client.Pages (next links only inside the
    instance), merges JSON-array pages into one array; a non-array first
    page is printed as-is.
  - JSON is indented on a TTY, verbatim otherwise. On status >= 400 the
    body goes to stdout and the classified error to stderr (exit 4/11/12/
    13/14). Requires auth (exit 4) via Factory.ClientFor.
  - {owner}/{repo}/{branch} placeholders -> usage error until Phase 2.
- internal/cli/api/api_test.go (TLS httptest server, FJO_HOST + FJO_TOKEN):
  GET, TTY pretty print, query/JSON fields, @file/@-, --input, headers,
  error statuses -> exit codes, --include/--silent, pagination incl.
  relative next links and refusal of a foreign next link, absolute URL
  outside the instance, not logged in, usage errors.
- docs/commands.md: `fjo api` section. docs/compatibility.md: auth + api
  marked done, FJO_TOKEN/FJO_HOST done, api differences listed.
