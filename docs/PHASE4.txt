# Phase 4 — Release management: postup a checklist

Cieľ: v0.2.0 (IMPLEMENTATION.txt §16 Phase 4; špecifikácia §5.6, §7.4, §9.2,
§10, §15). Fáza 3 je hotová a v0.1.0 je vydaná (2026-11-18).

Fáza je rozdelená na míľniky. Každý skončí samostatným PR, ktorý prejde
`make check`, lintom a integráciou na Forgejo 15 a 17 (§17.2, §18).

  4a  API vrstva pre releasy + `release list`, `release view`
  4b  `release create`, `release edit`, `release delete`
  4c  Prílohy: `release upload`, `release delete-asset` (streamovanie)
  4d  `release download` (streamovanie, integrita, prerušenie)
  4e  Binárne vydania fjo (GoReleaser), dokumentácia, uzavretie fázy

Endpointy a modely sú v swaggeri 15.0.11 a 17.0.1 zhodné:

  GET    /repos/{o}/{r}/releases                 draft, pre-release, q, page, limit
  POST   /repos/{o}/{r}/releases                 CreateReleaseOption
  GET    /repos/{o}/{r}/releases/latest
  GET    /repos/{o}/{r}/releases/tags/{tag}
  DELETE /repos/{o}/{r}/releases/tags/{tag}
  GET    /repos/{o}/{r}/releases/{id}            PATCH (EditReleaseOption), DELETE
  GET    /repos/{o}/{r}/releases/{id}/assets     POST (multipart alebo octet-stream, ?name=)
  GET    /repos/{o}/{r}/releases/{id}/assets/{attachment_id}   PATCH, DELETE
  GET    /settings/attachment                    enabled, max_size, max_files, allowed_types
  GET    /repos/{o}/{r}/tags/{tag}               DELETE (pre --verify-tag, --cleanup-tag)

## 4a — API vrstva, `release list`, `release view`

- [x] `internal/api/releases.go`: modely `Release`, `Attachment`,
      `CreateReleaseOptions`, `EditReleaseOptions`. Endpointy zaregistrovať
      v `endpoints.go`, aby ich overil swagger test.
- [x] `ReleaseByTag`: `/releases/tags/{tag}`, pri 404 záložne zoznam
      s `draft=true` (B-51). `LatestRelease`, `ListReleases` so stránkovaním.
- [x] Normalizovaný JSON model (§10.2) s názvami polí podľa gh:
      `tagName`, `name`, `body`, `isDraft`, `isPrerelease`, `createdAt`,
      `publishedAt`, `url`, `tarballUrl`, `zipballUrl`, `targetCommitish`,
      `author{login}`, `assets[{name,size,url,downloadCount,createdAt}]`, `id`.
      Golden testy na schému.
- [x] `release list`: `-L/--limit` (default 30), `--exclude-drafts`,
      `--exclude-pre-releases`, `-O/--order asc|desc`, `--json/--jq/--template`.
      Tabuľka v TTY: Title, Type (Latest/Draft/Pre-release), Tag, Published.
      Bez TTY TSV. Prázdny výsledok hlási na stderr.
- [x] `release view [<tag>]`: bez tagu ukáže najnovší release. Flagy `-w/--web`
      a `--json/--jq/--template`. Vypíše poznámky a prílohy (meno, veľkosť).
- [x] Testy: httptest (draft fallback, latest bez releasov = exit 12),
      integrácia 15 a 17.

## 4b — `release create`, `release edit`, `release delete`

- [x] `release create [<tag>]`:
  - [x] Flagy `-t/--title`, `-n/--notes`, `-F/--notes-file` (`-` = stdin),
        `-d/--draft`, `-p/--prerelease`, `--target`, `--verify-tag`,
        `--notes-from-tag` (anotácia tagu cez git) a `--hide-archive-links`
        (iba vo Forgejo).
  - [x] Ak tag neexistuje, Forgejo ho vytvorí z `--target` (default vetva).
        S `--verify-tag` je chýbajúci tag chyba (exit 12).
  - [x] Súbory uvedené za tagom sa nahrajú vo fáze 4c. Ak upload zlyhá, release
        ostane ako draft a chyba povie, ako pokračovať (`release upload`).
  - [x] TTY bez tagu alebo titulku sa pýta. Bez TTY je tag povinný
        (exit 10). Poznámky môžu byť prázdne.
  - [x] Release s existujúcim tagom = exit 13 s čitateľnou správou.
- [x] `release edit <tag>`: `--tag` (premenovanie), `--title`, `--notes*`,
      `--draft[=false]` (publikovanie), `--prerelease[=false]`, `--target`.
      Mení iba zadané polia.
- [x] `release delete <tag>`: potvrdenie v TTY, bez TTY povinné `--yes`.
      `--cleanup-tag` zmaže aj git tag.
- [x] Testy: httptest pre každý flag, integrácia (create → edit → publish
      → delete s `--cleanup-tag`).

## 4c — Prílohy: `release upload`, `release delete-asset`

- [x] `release upload <tag> <files>...` (`--clobber`):
  - [x] Telo požiadavky je priamo otvorený súbor (B-52), takže sa súbor
        nikdy nenačíta celý do pamäte. Content-Length je známa.
  - [x] Pred uploadom načítať `/settings/attachment`. Ak sú prílohy vypnuté,
        exit 15. Prekročený `max_size` alebo `max_files` a nepovolený typ
        oznámiť ešte pred odoslaním. HTTP 413 namapovať na rovnakú správu.
        Odchýlka: kontroluje sa iba `enabled`, limity patria k sekcii
        [attachment], nie k releasom (B-57). 413 = exit 13.
  - [x] Upload sa nikdy neopakuje automaticky, telo sa nedá prehrať znova
        (`isReplayable`). HTTP klient nesmie mať celkový timeout, ktorý by
        ukončil veľký prenos (iba ResponseHeaderTimeout).
  - [x] Existujúca príloha s rovnakým menom = exit 13. `--clobber` ju
        nahradí podľa B-54.
  - [x] Priebeh na stderr iba v TTY, bez TTY nič.
  - [x] Viac súborov: postupne, pri chybe zastaviť a vypísať, čo sa nahralo.
- [x] `release delete-asset <tag> <name>`: potvrdenie, bez TTY `--yes`.
- [x] Testy: veľký súbor (napr. 64 MiB generovaný v teste) s meraním
      alokácií, aby sa preukázalo, že sa nebufferuje. Ďalej 413, vypnuté
      prílohy, clobber, integrácia 15 a 17.

## 4d — `release download`

- [x] `release download [<tag>]`: bez tagu najnovší release.
  - [x] Flagy `-p/--pattern` (glob, opakovateľný), `-A/--archive zip|tar.gz`,
        `-D/--dir`, `-O/--output` (`-` = stdout), `--clobber`, `--skip-existing`,
        `--skip-verify`.
  - [x] Bez `--pattern` a `--archive` stiahne všetky prílohy (ako gh).
  - [x] Streamovanie do dočasného súboru v cieľovom adresári, potom kontrola
        veľkosti, fsync a rename (B-53). Pri chybe, Ctrl-C alebo zrušení
        kontextu sa dočasný súbor zmaže. Exit 130 pri prerušení.
  - [x] SHA-256 podľa manifestu kontrolných súčtov, ak je v release (B-53).
        Nesúlad = exit 1 a súbor sa zmaže.
  - [x] Token sa posiela iba na vlastný host (§7.4). Pri presmerovaní na iný
        host (externé prílohy, CDN) sa hlavička Authorization nesmie
        preniesť. Overiť testom.
  - [x] Mená príloh zo servera sú nedôveryhodné: odmietnuť `..`, cesty,
        absolútne mená a na Windows rezervované mená. Výsledná cesta musí
        ležať v `--dir`.
  - [x] Existujúci súbor = chyba, pokiaľ nie je `--clobber` alebo
        `--skip-existing` (B-54).
- [x] Testy: prerušený prenos nenechá súbor, nesúlad veľkosti aj
      kontrolného súčtu, path traversal v mene prílohy, presmerovanie bez
      tokenu, integrácia 15 a 17 (upload → download → porovnanie).

## Kontrola pred uzavretím (acceptance criteria, Phase 4)

- [x] Releasy sa dajú spravovať bez prehliadača: list, view, create, edit,
      delete, upload, delete-asset, download (integrácia 15 a 17).
- [x] Veľké prílohy sa pri uploade ani downloade nenačítajú celé do pamäte
      (test s meraním alokácií).
- [x] Prerušené operácie so súbormi zlyhajú bezpečne: žiadny čiastočný súbor
      s finálnym menom, žiadna polovičná príloha bez chybovej správy.
- [x] Všetky `list` a `view` príkazy majú `--json/--jq/--template`.
- [x] Bez TTY nič nečaká na vstup. Deštruktívne príkazy vyžadujú `--yes`.
- [x] Token sa nikdy nedostane na iný host ani do `--debug` výstupu.
- [x] `make check`, lint (vrátane fmtwrite), race a integrácia prechádzajú
      na Linuxe, Windowse a macOS.
- [ ] Tag v0.2.0 vytvorí cez GoReleaser release s binárkami, checksumami a SBOM.
      Overené lokálne snapshotom (bez SBOM) a v CI jobom `goreleaser`;
      čaká na tag po merge.
