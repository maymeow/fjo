# Phase 3 — Issues a pull requesty: postup a checklist

Cieľ: v0.1.0 (IMPLEMENTATION.txt §16, Phase 3; špecifikácia §5.4, §5.5, §10, §11).
Fáza 2 (2a + 2b) je hotová, toto je ďalší krok.

Rovnako ako pri fáze 2 je fáza rozdelená na menšie míľniky. Každý z nich
skončí samostatným commitom, ktorý prejde testami (§17.2, §18 Definition of done).

  3a  Výstupná infraštruktúra (--json/--jq/--template, tabuľky, pager, editor)
  3b  Issues
  3c  PR, iba čítanie (list, view, diff, checks)
  3d  PR, zápis (create, checkout, merge, close/reopen/ready/edit/comment)
  3e  PR review + upratanie, dokumentácia, uzavretie fázy

## 3a — Výstupná infraštruktúra

Stav: hotovo 2026-11-16.

Spoločné časti pre všetky príkazy, ktoré niečo vypisujú. Najprv ich treba
doplniť do existujúcich `repo list`/`repo view`, až potom pridávať issues.

- [x] Balík `internal/cli/cmdutil` (alebo nový `internal/output`):
  - [x] `AddJSONFlags(cmd, fields []string)` registruje `--json`, `--jq` a `--template` (B-2).
  - [x] Ak `--json` nemá polia, skončí usage chybou (exit 10) a vypíše
        dostupné polia zoradené ako v gh.
  - [x] Neznáme pole vráti usage chybu so zoznamom polí.
  - [x] `--jq` a `--template` bez `--json` skončia usage chybou.
  - [x] `--jq` cez gojq. Pri chybe výrazu exit 10 a čitateľná správa.
  - [x] `--template` cez text/template s podmnožinou gh helperov
        (`tablerow`, `tablerender`, `timeago`, `color`, `join`, `pluck`, `truncate`).
- [x] Normalizované JSON modely (§10.2), nie surové Forgejo štruktúry:
  - [x] `Issue`, `PullRequest`, `User{login}`, `Label{name,color}`,
        `Milestone{title,number}`, `Comment`, `Review`, `Check`.
  - [x] Názvy polí podľa gh, kde sa dá (`number`, `title`, `state`, `author`,
        `url`, `createdAt`, ...). Odchýlky zapísať do compatibility.md.
  - [x] Typy a nullability sú stabilné. Na schému napísať golden testy.
- [x] Table printer:
  - [x] TTY: zarovnané stĺpce, rešpektuje šírku terminálu, skracuje s `…`
        a je Unicode-aware.
  - [x] Bez TTY: TSV bez farieb a bez skracovania (rovnako ako gh).
  - [x] Farby iba ak je povolené `--color`/NO_COLOR/CLICOLOR_FORCE.
  - [x] Hlášky pre prázdny výsledok idú na stderr, napr.
        „no open issues in owner/repo“.
  - [x] Výpis `repo list` presunúť z tabwriter na nový printer.
- [x] Pager:
  - [x] Poradie: `FJO_PAGER` > config `pager` > `PAGER` > `less -FRX`.
  - [x] Flag `--no-pager`, platí iba pre príkazy s dlhým výstupom.
  - [x] Pager sa nespúšťa, ak stdout nie je TTY, ani pri `--json`.
  - [x] Windows: ak pager neexistuje, výstup ide priamo (B-28).
- [x] Editor pre telo issue/PR:

        default podľa OS.
  - [x] Dočasný súbor s právami 0600, po skončení sa zmaže.
  - [x] Prázdny obsah = zrušenie (exit 2).
- [x] Spoločné flagy pre telo: `--body`, `--body-file` (`-` = stdin) a

- [x] Doplniť `--json` do `repo list` a `repo view`.
- [x] Testy: výber polí, jq, template, tabuľka TTY vs. bez TTY, výber pagera

## 3d — PR, zápis

- [ ] (*) `pr create`:
  - [ ] Head = aktuálna vetva. Ak je detached HEAD, chyba.
  - [ ] Push remote a upstream sa zisťujú z git configu.
  - [ ] Base = `--base`, inak default vetva repa (§5.5: iba ak je to
        jednoznačné).
  - [ ] Head z forku vo formáte `owner:branch`.
  - [ ] Ak vetva nie je na serveri, správanie podľa rozhodnutia z bodu 0
        (push alebo chyba).
  - [ ] `--fill` a `--fill-first`: titulok a telo z commitov `base..head`.
  - [ ] `--draft` = prefix `WIP: ` v titulku (B-31).
  - [ ] Ďalšie flagy: `--title`, `--body*`, `--label`, `--assignee`,
        `--reviewer`, `--milestone`, `--web`.
  - [ ] Existujúci otvorený PR pre rovnaký head/base je chyba s jeho URL
        (exit 13).
  - [ ] Bez TTY: bez `--title` alebo `--fill` je to chyba.
- [ ] (*) `pr checkout <num>`:
  - [ ] Fetch `refs/pull/<n>/head` do lokálnej vetvy (meno = head branch,
        prípadne `--branch`).
  - [ ] Nikdy neprepíše lokálne zmeny (§5.5): špinavý working tree = chyba.
  - [ ] Ak vetva existuje a nedá sa fast-forwardovať, chyba. Prepísať ju
        dovolí iba `--force`.
  - [ ] Hodnoty zo servera ako argumenty pre git vždy za `--`, rovnaké
        spevnenie ako v 5dffb4a.
  - [ ] Pri PR z forku nastaviť upstream, ak sa dá. Inak iba lokálna vetva.
- [ ] (*) `pr merge [<num>]`:
  - [ ] `--merge|--squash|--rebase`, plus Forgejo `rebase-merge` a
        `fast-forward-only`, ak ich swagger obsahuje.
  - [ ] Povolené metódy sa zistia z nastavení repa
        (`allow_merge_commits`, `allow_squash_merge`, ...) (§5.5).
        Nepovolená metóda = exit 15 so zoznamom povolených.
  - [ ] V TTY výber metódy, ak nie je zadaná. Bez TTY je flag povinný.
  - [ ] `--delete-branch` maže vzdialenú vetvu cez API a lokálnu vetvu iba
        vtedy, keď na nej práve nie si.
  - [ ] `--subject`, `--body*` pre merge commit.
  - [ ] `--auto` cez `merge_when_checks_succeed`, ak to existuje vo verzii
        15 aj 17.
  - [ ] Nemergeovateľný PR alebo konflikt = exit 13 s čitateľnou správou
        (SHA nesmie byť zredigované, B-37).
- [ ] `pr close <num>`: flagy `--comment` a `--delete-branch`.
- [ ] `pr reopen <num>`.
- [ ] `pr ready <num>`: odstráni WIP prefix. `--undo` ho pridá späť.
- [ ] `pr edit <num>`: rovnaké flagy ako `issue edit` a navyše `--base`
      a `--add-reviewer`/`--remove-reviewer`.
- [ ] `pr comment <num>`.
- [ ] Testy:
  - [ ] Git integrácia (temp repo + bare remote): create detekcia, checkout
        (čistý stav, špinavý stav, existujúca vetva, --force).
  - [ ] Integrácia Forgejo 15 a 17: create, merge (každá povolená metóda),
        close, reopen, ready.
