# FJO — Backlog, Ideas & Open Decisions

Everything that is NOT (yet) part of docs/IMPLEMENTATION.txt:
new feature ideas, scope changes, open questions and decisions taken during development.

- Work actually done      -> docs/CHANGELOG.txt
- Agreed plan / contract  -> docs/IMPLEMENTATION.txt
- Everything else         -> here

When an item is accepted into the plan, update IMPLEMENTATION.txt, mark the item
here as "Accepted -> §X" and log the spec change in CHANGELOG.txt.

## Open decisions

Source of B-1 .. B-32: review of IMPLEMENTATION.txt v1.0 on 2026-11-13.
"Before Phase 0" items block the start of implementation.

Guiding constraint (user, 2026-11-13): fjo is meant to be an ALTERNATIVE TO
GitHub CLI (gh). Where an open decision has a gh-aligned option, that option
is the default recommendation unless Forgejo semantics differ. See B-20.

### B-20 — Level of gh compatibility (umbrella decision)
Type:     decision
Status:   accepted -> §1.4
Added:    2026-11-13
Phase:    before Phase 0

Context:
- §1.1 says "comparable to gh"; product goal is to be a gh alternative, so
  users, scripts and coding agents should be able to switch with minimal
  relearning.
Proposal / options:
- Commit to a written compatibility policy in docs/compatibility.md:
  - Same command/subcommand names and flag names as gh wherever the
    Forgejo feature exists (e.g. `pr create --base/--head/--fill/--draft`,
    `issue list --state/--label/--assignee/--limit`, `-R/--repo`, `--web`).
  - Same `--json <fields>` / `--jq` / `--template` behaviour and, where
    possible, the same JSON field names as gh (`number`, `title`, `state`,
    `author.login`, `url`, `headRefName`, ...).
  - Same exit-code meanings as gh (B-11), extended only above gh's codes.
  - Same env-var model with FJO_ prefix (GH_TOKEN->FJO_TOKEN,
    GH_HOST->FJO_HOST, GH_REPO->FJO_REPO, GH_PAGER->FJO_PAGER,
    GH_PROMPT_DISABLED->FJO_PROMPT_DISABLED) and honour NO_COLOR,
    CLICOLOR_FORCE, PAGER, EDITOR/VISUAL.
  - Every intentional difference from gh is listed with a reason.
- Maintain a parity table (gh command -> fjo status: done / planned /
  not applicable on Forgejo / different semantics).
Decision:
- 2026-11-13: Maximum gh compatibility where Forgejo allows it (user: "alternative to gh, but for Forgejo"; explicit choice left to Claude, recommended option taken). Forgejo semantics win where they differ; every deviation documented in docs/compatibility.md. Exit codes follow from this -> B-11 option B (table to be finalized in Phase 0).

### B-1 — Replace Viper with plain YAML + own precedence logic
Type:     decision
Status:   accepted -> §2, §6
Added:    2026-11-13
Phase:    before Phase 0

Context:
- Viper uses "." as key delimiter and lowercases keys. Host keys such as
  `hosts: git.example.com:` (§6 example) are split into nested keys.
Proposal / options:
- A) Drop Viper; use a YAML library + application-owned precedence
     (flag > env > repo-local > user > default), fully unit-tested.
- B) Keep Viper, change config shape so hosts are a list, not map keys.
Decision:
- 2026-11-13: A) Viper dropped. YAML library + application-owned precedence (flag > env > repo-local > user > default). Reason: hostnames as map keys must work; fewer dependencies; fully unit-testable.

### B-2 — `--json` flag semantics
Type:     decision
Status:   accepted -> §1.4, §5.1, §10.2
Added:    2026-11-13
Phase:    before Phase 0

Context:
- §5.1 says bare `--json` returns the default object, §10.2 shows
  `--json number,title,state`. With pflag optional values (NoOptDefVal)
  the space-separated form parses `number,title,state` as a positional arg;
  only `--json=number,title` works.
Proposal / options:
- A) `--json <fields>` always requires fields (gh behaviour); bare `--json`
     prints the list of available fields.
- B) Separate `--format json` + `--fields a,b,c`.
- Recommendation (B-20, gh alternative): A.
Decision:
- 2026-11-13: A) gh semantics: `--json <fields>` requires fields; bare `--json` fails with the list of available fields. `--jq` and `--template` require `--json`. Reason: gh compatibility (B-20).

### B-3 — Canonical host identity
Type:     decision
Status:   accepted -> §6.2
Added:    2026-11-13
Phase:    before Phase 0

Context:
- Config is keyed by hostname; §7.5 talks about "server origin".
  Not covered: non-default ports, subpath installs
  (https://example.com/forgejo/), http vs https, SSH alias pointing
  to a different hostname than the web/API host.
Proposal / options:
- Define a canonical host ID (normalized origin + base path) used as the key
  in config and keyring; map SSH hosts/aliases to it explicitly.
Decision:
- 2026-11-13: Canonical host ID = normalized origin + base path (lowercase host, default port and trailing slash removed, https implied; e.g. `git.example.com`, `git.example.com:3000`, `example.com/forgejo`). Plain http only with explicit per-host opt-in. SSH hosts/aliases are mapped to a host ID via `ssh_hosts` in config.

### B-4 — Account model
Type:     decision
Status:   accepted -> §6, §7.5
Added:    2026-11-13
Phase:    before Phase 0

Context:
- Unclear whether "account" is a user-chosen alias (`personal`) or the
  server username; what `auth switch --host` does with multiple accounts
  on one host; what the keyring key looks like.
Proposal / options:
- Account = (host ID, username); optional alias only for display/selection.
  `auth switch --host H [--user U]`, error when ambiguous and non-interactive.
Decision:
- 2026-11-13: Account identity = (host ID, server username), as in gh. One active user per host; `auth switch --host H [--user U]`. Keyring entry per (host ID, username). Ambiguous identity without a terminal -> write operations fail. Named account aliases (old §6 `accounts:`) removed.

### B-5 — Credential storage when OS keyring is unavailable
Type:     decision
Status:   accepted -> internal/credentials
Added:    2026-11-13
Phase:    Phase 1

Context:
- §7.2 forbids plaintext fallback. On headless Linux, WSL, containers and CI
  Secret Service is usually missing -> no persistent login for admins.
Proposal / options:
- A) Explicit opt-in file store (0600, `--insecure-storage`, loud warning,
     shown in `auth status`).
- B) Read token from git credential helper.
- C) Env-only (FJO_TOKEN) as today.
- Also pick keyring library (zalando/go-keyring vs 99designs/keyring).
Decision:
- 2026-11-13: A) like gh: zalando/go-keyring; keyring failure is an error with a hint; `auth login --insecure-storage` stores the token in credentials.yaml (0600, separate from config.yaml), shown as "insecure storage" in auth status.

### B-12 — Global vs. per-command flags
Type:     decision
Status:   accepted
Added:    2026-11-13
Phase:    Phase 0

Context:

  not distinguished. Both `--version` and `fjo version` exist.
Proposal / options:
- Truly global: --host, --color, --no-pager, --debug, --help.

Decision:
- 2026-11-13: gh model: no global --host/--repo; auth commands take -h/--hostname (hidden --host alias), `api` takes --hostname. --verbose = progress on stderr, --debug = sanitized HTTP trace. Output/repo flags per command group (Phase 2/3).

### B-36 — Redactor masks ordinary words after "token"
Type:     tech-debt
Status:   open
Added:    2026-11-13
Phase:    Phase 2 (before more user-facing messages mention tokens)

Context:
- internal/logging/redact.go: the bare-credential rule
  `(?i)\b(token|bearer)\s+[A-Za-z0-9._~+/=-]{8,}` treats any word of 8+
  characters after "token" as a secret. "no token provided" was printed as
  "no token REDACTED"; the message was reworded to "no token was provided"
  (Phase 1), which only works around this one case. Future errors such as
  "token required" / "token rejected" / "token settings" hit it too.
Proposal / options:
- A) Require a credential-like value: at least one digit and length >= 20
  (Forgejo PATs are 40 hex; JWT/bearer values are long and mixed).
- B) Match bare "token X" only in HTTP-ish contexts (after "Authorization",
  in debug HTTP traces) and rely on registered exact secrets otherwise
  (FJO_TOKEN and stored tokens are already registered with the redactor).
- Either way add regression tests with plain English phrases next to the
  existing secret-shaped cases.
Decision:
-
